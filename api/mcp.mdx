```text Server URL
https://api.kviria.com/mcp
```

Kviria's Model Context Protocol (MCP) server (`2.1.0`) runs over **streamable HTTP** and exposes **three read-only tools** backed by the exact same contracts, limits, and validation as the HTTP API:

| Tool | Equivalent endpoint | What it does |
|---|---|---|
| `kviria` | [`POST /v1/agent`](/api/agent) | Resolve a place, address, apartment building, transit stop, or intersection; handle nearby, across, next-to, and multi-turn follow-ups |
| `kviria_profile` | [`POST /v1/profile`](/api/profile) | Profile and compare street class, arterial distance, building context, walking amenities, neighborhood demographics, bare-earth terrain, and location claims for `1` to `5` US locations |
| `kviria_batch` | [`POST /v1/batch`](/api/batch) | Ground `2` to `15` stops, order a walking itinerary, or compute a fair meeting point for `2` to `5` people |

All three tools advertise read-only MCP tool annotations (`readOnlyHint: true`, `destructiveHint: false`, `openWorldHint: false`; `idempotentHint: true` on stateless `kviria_profile` and `kviria_batch`, `false` on stateful `kviria`) and return structured JSON content (`structuredContent`) alongside plain JSON text.

## Authentication (OAuth 2.1 or API key)

- **OAuth 2.1 with PKCE (`S256`):** Unauthenticated calls to `https://api.kviria.com/mcp` return `401 Unauthorized` with a `WWW-Authenticate` header pointing to `https://api.kviria.com/.well-known/oauth-protected-resource/mcp`. Kviria supports **Client ID Metadata Documents (CIMD)** (`client_id_metadata_document_supported: true`) and **Dynamic Client Registration** (`/oauth/register`).
- **One-click connect:** Approving access on `https://api.kviria.com/authorize` creates a free account (`600` credits/day) in one click, with no email, password, or OTP required.
- **Static API key:** Clients that send fixed headers can pass `Authorization: Bearer kvr_...` from [api.kviria.com/key](https://api.kviria.com/key).

## Connect your client

<Tabs>
  <Tab title="Claude">
    **Claude (custom connector, supported plans):** Add `https://api.kviria.com/mcp` as a custom connector and click **Allow** on the Kviria connect page.

    **Claude Code:**

    ```bash
    claude mcp add --transport http kviria https://api.kviria.com/mcp
    ```
  </Tab>

  <Tab title="ChatGPT / Codex">
    **ChatGPT (Developer Mode / supported plans):** Add `https://api.kviria.com/mcp` as a custom remote MCP connector in Settings and approve access on the Kviria connect page (OAuth 2.1 discovery and CIMD work automatically).

    **Codex:**

    ```bash
    codex mcp add kviria --url https://api.kviria.com/mcp
    ```
  </Tab>

  <Tab title="Perplexity">
    Register `https://api.kviria.com/mcp` as a remote Streamable HTTP connector under **Connectors** (on supported plans) using OAuth or a Bearer key from [api.kviria.com/key](https://api.kviria.com/key).
  </Tab>

  <Tab title="Cursor / VS Code">
    Add Kviria to your workspace config (OAuth opens automatically on first use):

    **Cursor (`.cursor/mcp.json`):**

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "kviria": {
          "url": "https://api.kviria.com/mcp"
        }
      }
    }
    ```

    **VS Code (`.vscode/mcp.json`):**

    ```json .vscode/mcp.json
    {
      "servers": {
        "kviria": {
          "type": "http",
          "url": "https://api.kviria.com/mcp"
        }
      }
    }
    ```
  </Tab>

  <Tab title="API key header">
    For headless agents or MCP clients that send static headers, pass a key from [api.kviria.com/key](https://api.kviria.com/key):

    ```json mcp.json
    {
      "mcpServers": {
        "kviria": {
          "type": "http",
          "url": "https://api.kviria.com/mcp",
          "headers": {
            "Authorization": "Bearer kvr_..."
          }
        }
      }
    }
    ```
  </Tab>
</Tabs>

<Note>
  **Notes for MCP callers:** When calling `kviria`, omit `anchor` on follow-up turns if the user has not moved (never send an empty `anchor: {}` object), and pass the returned `state` string into the next `kviria` call. `kviria_profile` and `kviria_batch` are stateless single-shot tools. MCP requests do not need `x-kviria-agent`.
</Note>
