```text Endpoint
POST https://api.kviria.com/v1/batch
Authorization: Bearer kvr_...
Content-Type: application/json
Max body: 16 KB
MCP tool: kviria_batch
```

`POST /v1/batch` (exposed over MCP as `kviria_batch`) resolves multiple US places or addresses in parallel and computes walking clusters, non-zigzag visit orders, or fair meeting points.

Every call charges `1` credit per `3` requested items and candidates (`1` to `5` credits). See [Rate limits and errors](/api/limits).

## Modes

| Mode | Items | Purpose |
|---|---|---|
| `"ground"` | `2` to `15` | Resolve each stop to coordinates, flag ambiguous or multi-branch names, compute a pairwise distance/walk matrix, and group nearby stops into walking clusters (`clusters` + `outliers`). |
| `"sequence"` | `2` to `15` | Everything in `"ground"` plus an ordered non-zigzag `sequence` (`order`, `legs`, `totalDistanceM`, `totalWalkM`), optionally anchored at a `start` coordinate. |
| `"meet"` | `2` to `5` | Compute a fair meeting zone (`geometricMedian`, `minimaxCenter`, and active dining/cafe `hub`) and return up to `5` venue `suggestions` with per-participant `distanceM` and `walkM`. |

## Request body

| Field | Type | Required | Description |
|---|---|---|---|
| `mode` | `"ground" \| "sequence" \| "meet"` | Yes | Batch operation mode. |
| `items` | array | Yes | `2` to `15` items (`2` to `5` for `meet`). Each item accepts optional unique `id` (`<= 64` chars, defaults to `item_1`...), optional per-item `area`, and **exactly one** of `query` (`<= 240` chars, auto-classified as inline `lat, lng`, street address, or named place/neighborhood) or `anchor` (`{ lat, lng }`). If both `anchor` and `area` are sent on the same item, `anchor` takes precedence and a warning entry (`area_ignored_with_anchor`) is recorded in `evidence`. |
| `area` | string | No | Default US area (`"Austin, TX"`, `"Manhattan, NY"`) applied to items without their own `area`. |
| `start` | `{ lat, lng }` | No | Optional starting point for `ground` or `sequence` mode only. |
| `clusterRadiusM` | number | No | Walking cluster radius in meters (`200` to `3000`, default `800`). Valid for `ground` and `sequence` only. |
| `kind` | string | No | Category to search around the fair midpoint (`"cafe"`, `"restaurant"`, `"bar"`; default `"restaurant"`). Valid for `meet` only. |
| `candidates` | array (`1` to `15`) | No | Caller-supplied meeting-venue candidates to score for physical fairness across participants (same shape as `items`, default IDs `cand_1`...). Valid for `meet` only. |

## Response notes

- **Ambiguity preservation:** Multi-branch chains or ambiguous names return `status: "ambiguous"` with up to `3` `candidates` rather than guessing; remaining items still resolve and sequence cleanly.
- **Street walking vs. straight-line distances:** `meet` computes street-network `walkM` across walkable corridors (`corridorWalkMode: "street_graph"`), falling back to straight-line distances on wider metro spans (`walkM: null`, `corridorWalkMode: "straight_line_fallback"`).
- **External candidates (`meet`):** When you pass `candidates[]`, Kviria resolves and ranks those exact venues by fairness across all participants (`hub.source: "external_candidates"`), returning any unresolved entries under `meet.unresolvedCandidates`.
